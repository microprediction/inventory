The imbalance symmetry

Companion demo to On a Simple Relationship Between Order Imbalance, Skew and Width in Over-The-Counter Trading.

A dealer faces sealed-bid enquiries that are sellers with probability $q$ and buyers with probability $1-q$. The theorem states that the imbalanced problem is the balanced one in disguise: solve the balanced problem with carrying cost multiplied by $M(q) = 1/(2\sqrt{q(1-q)})$ and tilt the indifference cost by $\delta = \tfrac{w}{2}\log\tfrac{q}{1-q}$ per unit. (The widening $\gamma$ is the same factor as $M(q)$ read in the overhead frame, not a further correction.) Below, both capped finite-lattice problems are solved numerically and independently by policy iteration. The exact comparison is shown only after every available quote is strictly positive and the two actual jump generators agree term by term.

The dots landing on the line. In the verified interior region that coincidence is the theorem, and the “max quote-map error” readout is solver precision, not approximation. If a zero-markup floor binds, the comparison is suppressed because the constrained problem has changed.

Near balance the skew shift is linear in the imbalance while the width change is quadratic — why practitioners skew before they widen. The width change is the imbalanced dealer's width at a flat book minus the balanced dealer's at the same carrying cost; it comes entirely from the multiplied carry, so it depends on the carry slider. The width curve includes only q values for which all three capped policies used in that comparison are strictly interior; it stops when a quote floor binds. The vertical hairline marks the current slider value of q.

Model and solver: capped exponential best-competitor with width w = 1, adverse-selection cost ε = 0.15 and grid x = −6…6. Independent finite-state policy iterations use the actual one-sided cap rows and the zero-markup floor (fourcorners_core.js, symmetry_core.js). The focused regression is docs/verify_symmetry.js.
